## 2025-02-14 - Fix Path Traversal & SSRF Risk in Internal LIS Proxy API
**Vulnerability:** The internal proxy API (`/api/lis/download-report` in `server.ts`) directly interpolated user-provided inputs (`patientId` and `reportId`) into a backend URL used with `fetch` without any sanitization or encoding. This could allow Path Traversal attacks (e.g., passing `../` to access unintended backend API paths) and potentially lead to Server-Side Request Forgery (SSRF) if the backend URL parser behaves unexpectedly.
**Learning:** Even though `patientId` and `reportId` conceptually seem like simple strings, when they are dynamically appended to server-to-server HTTP request URLs, they become an attack vector. The server implicitly trusts the input and can be tricked into making requests outside the intended scope.
**Prevention:** Always validate that inputs are of the correct type (e.g., `typeof value === 'string'`) and explicitly encode any URL parameters (e.g., using `encodeURIComponent`) before interpolating them into a URL for server-side `fetch` or HTTP client calls.
